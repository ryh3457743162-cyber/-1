## 数据与接口

实际存储是 JSON，而非 SQL/ORM。复用 `title`、`uploaded`，新增可选 `shotDate`（`YYYY-MM-DD` 或 `null`）。上传照片存入原 `photos` 记录，历史内置照片的覆盖值存入既有 `seedStates`。

旧记录缺少 `shotDate` 时按未知日期处理，不需要 migration，也不会批量改写历史数据。

`PATCH /api/manage/photos/<photo_id>` 复用管理员 Session 鉴权、照片生命周期锁和原子 JSON 写入。仅接受 `title` 和 `shotDate`；拒绝未知字段。名称去首尾空格、1–60 字符；日期校验真实日历，不做 UTC 转换。回收站照片返回 409，恢复后可编辑。保存失败返回安全提示，不泄露底层错误。

## 年份与书本

- `year` 仍是原手动归档年份，上传时间 `uploaded` 不变。
- 图集/平面按 `shotDate` 的年份分组；未知日期沿用 `year`。
- 已知日期按时间正序；未知日期保留原相对顺序。
- 书本仍按原归档年份、pageId、order、photoId、slot 展示；不会按拍摄日期重新排版。
- 同一浏览器的前台通过 storage 通知更新；切回前台及刷新页面也会重新读取。没有新增轮询或 WebSocket。
- 元数据更新保持书本当前页；audio 不重建。不同浏览器已打开页面需刷新/重新进入以读取新值。
